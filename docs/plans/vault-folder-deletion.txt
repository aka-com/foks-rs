Safe desktop empty-folder deletion plan (revised before implementation)

Scope
Delete only empty, real folders in account and team vaults. Root folders are not
deletable. Preserve the selected source dirent version. Never silently fall back
to recursive deletion or to a legacy unguarded request. Existing explicit
recursive callers and moves retain their behavior.

Rejected initial design
A full namespace version vector alone does not assert emptiness: the server only
checks the versions of supplied existing dirents. Inserting a new child does not
advance directory/root versions, so an empty listing and subsequent ordinary
unlink race. Advisory KV locks are not enforced by put. This was discovered in
the final pre-implementation server transaction review; no unsafe code shipped.

Implementation
1. Add explicit Rust-extension capability negotiation for atomic empty-directory
   assertions. Do not change the meaning of the existing identity version reply.
   Unknown Go/older servers fail closed before journaling or sending a removal.
2. Add a dedicated KvExtensions asserted Put method containing a bounded list of
   assertions. Each assertion carries source parent ID, source dirent ID, selected
   source version, and child directory ID. Ordinary two-argument Put is unchanged.
   A distinct method prevents old servers from ignoring unknown trailing fields
   after a rolling downgrade or a recovered prepared journal.
   The server validates source binding and requires the matching tombstone. In
   the same SQLite writer transaction, inspect latest live child heads and refuse
   a nonempty directory before applying any mutation. Exact committed replay can
   return success because the guarded deletion has already completed.
3. Persist the assertions in protected namespace outbox material and its request
   hash. Decode old two-field material and new three-field material. Recovery
   reconstructs the same asserted request, never a legacy Put. Recheck capability
   before replaying a prepared asserted request. Unknown delivery stays read-only
   reconciliation, without retrying the user action.
4. Nonrecursive directory unlink loads authenticated source/child facts and
   rejects a nonempty/inaccessible child before preparing the write. Preserve
   source version across stale-cache retries and repeat local validation; server
   assertions remain authoritative for concurrent new children. Recursive unlink
   and directory moves keep ordinary Put and their existing semantics.
5. Desktop native removal retains ExactVersion and recursive=false. Only real
   catalog folders can supply versions; synthetic folders and root remain
   unavailable. Confirmation states empty-only behavior. During dispatch, block
   dismissal/navigation. A failed refresh after acknowledged success cannot
   offer to replay removal. Capability refusal explains unsupported servers.
6. Tests cover empty success, nonempty refusal, source mismatch, source version
   change, concurrent child insertion before transaction, atomic rejection with
   no orphaned child, exact committed replay, persistence/recovery of assertions,
   absent/old capability refusal, untouched ordinary Put/recursive/move behavior,
   and frontend exact-version/in-flight ownership. Run focused native, Rust and UI
   tests, typecheck and lint. Keep this a separate commit from rename/move.

Revised plan review 1 -- concurrency and protocol (completed before implementation)
Explicit transaction assertions close the phantom-child gap that version vectors
cannot close. Bind assertions to the selected source, not a caller-provided
unrelated empty directory. Preserve assertions in exact durable bytes and refuse
unsupported servers. No global empty-only tombstone rule, since that would break
nonempty directory moves and existing explicit recursive unlink semantics.

Revised plan review 2 -- recovery and product (completed before implementation)
Unknown delivery must not become a legacy retry. Old journals remain decodable;
new prepared asserted journals require capability before submission. Exact
committed replay is success. UI only offers real, nonroot folder deletion and
states empty-only scope; lack of capability is an honest refusal. Server tests
must insert a child after the client's apparent empty snapshot, not merely test
an already-known nonempty folder. Two implementation-review passes required
before the separate folder commit.

Routing refinement review 1 -- fail-closed downgrade (before encoder change)
Use a distinct KvExtensions method for guarded Put, not an optional argument on
legacy kvPut. Capability alone is not a durable server-version guarantee: an old
server may silently ignore trailing fields after rollback. Unknown extension
methods fail closed. The client's nonempty persisted assertions select the guarded
encoder for first submission and recovery.

Routing refinement review 2 -- compatibility and ownership (before encoder change)
Keep legacy kvPut unchanged. New asserted method requires nonempty assertions;
request-limit, auth and version precondition checks still apply. Golden frames
cover the method identity and exact assertion payload. No downgrade/retry fallback.
