The recovery phrase row cage 32 gains an amber “Last tested: never” chip and a Test… button beside the existing Revoke… button. The Devices rail dot now also turns on for an untested phrase, and its label lists each reason, so it still reports the work account that has no recovery phrase. Today the row offers only Revoke… (devices-screen.tsx 445–457), and nothing checks a phrase after it is written down. Use Version above the window to compare.

Findings

  • gap-recovery-phrase-testShips on today's data
    The row, its Revoke… button, BackupEnrollmentSummary.backup_id_hex and the Devices dot (deviceAlertRegistry) already exist.
  • gap-recovery-phrase-testNeeds native shell
    The last-tested time must survive restarts on this device, and the device metadata cache is session-only (device-cache.ts). The finding puts the time in device-local metadata in the native shell. The webview storage the app already uses for nonsecret records such as invitation labels (invitation-labels.ts) is a frontend-only alternative. Either way the store holds a time, never phrase material.
  • gap-recovery-phrase-testNeeds agent/IPC
    Test… depends on the new local agent operation VerifyRecoveryPhrase (see C).

B · Test sheet

Test… opens a sheet with 17 fields that alternate word and number, in the order of the written copy. Word fields complete from the BIP-39 list. Each field reports its own problem as you type: an unknown word, a number above 8191, or a word where a number belongs, which usually means a skipped token. Today a recovery phrase is typed only during setup, into a single password field (signin-step.tsx), and the agent reports the first bad token after submit.

Findings

  • gap-recovery-phrase-testShips on today's data
    The grid, completion and as-you-type token checks are frontend work. They need the public BIP-39 English list in the frontend bundle; the desktop does not ship it today, and foks-crypto takes it from the bip39 crate. Paste splits a whole phrase across the fields, as pastePhrase keeps token boundaries today.
  • gap-recovery-phrase-testNeeds agent/IPC
    Test phrase sends the phrase to VerifyRecoveryPhrase as a SecretString. The agent parses it with BackupKey::from_owned_phrase, and its parse errors reuse recovery_phrase_sentence (agent main.rs 2258), so the agent remains the authority on what is valid.

Try

  • Type adv in field 3: Up and Down choose, Tab, Enter or Space accepts. Type advis to see “Unknown word”.
  • Type 9000 in a number field, or fill the grid with Typos.
  • Paste a whole phrase into field 1. Backspace in an empty field moves back.
  • Esc closes the completion list, then the sheet.

C · Results

The agent derives the backup key from the phrase and compares its entity ID with the backup keys in the account’s verified chain, without the network. A match names the phrase and its enrolment date and records the test on this device. A near miss uses the first word and number, which are the phrase’s public name, to say which phrase the copy belongs to and that the error is in positions 3 to 17. The key comparison cannot narrow it further. A copy of a revoked phrase is named, so it can be destroyed.

Findings

  • gap-recovery-phrase-testNeeds agent/IPC
    VerifyRecoveryPhrase{profile, account_alias, phrase} returns {matched_backup_id | null, matched_name, revoked} and zeroizes the phrase. It compares against the user chain the agent already holds, so it needs no network, protocol or server change. The same operation backs foks-rs recovery verify --phrase-file.
  • gap-recovery-phrase-testNeeds native shell
    A match writes the last-tested time to the device-local store, which turns the chip green and clears this phrase’s reason from the Devices dot.

D · First run

After the phrase is shown, a second step asks for three tokens from the written copy: word 4, number 6 and word 9. Done stays disabled until all three match, and a wrong entry names the position to compare. This replaces the “I have written this down” checkbox (first-run-recovery-step.tsx 106 and 236–248), which records intent but not a correct copy. The check compares with the phrase setup already holds in memory, so it needs no agent change.

Findings

  • gap-recovery-phrase-testShips on today's data
    The recall step uses recoveryPhrase, which the first-run step already holds before commitBackup. The copy now says “words and numbers”, since a HESP phrase is 9 words and 8 numbers.
  • gap-recovery-phrase-testNeeds native shell
    Counting this check as the phrase’s first test, so the 180-day clock starts at setup, needs the device-local store from A.
