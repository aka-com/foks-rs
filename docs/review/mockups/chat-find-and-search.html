Scenario

Engineering #deploys is extended for this mockup. The conversation holds its newest 50 rows, one CHAT_PAGE_ROWS page (#2,091–#2,140), back to Sep 30. The five Kit.data messages are #2,136–#2,140, and older history goes back to December 2025. Engineering #general has older history too. In the loaded rows, five messages from sam.ortiz, priya.n and deploy-bot contain “canary” seven times.

A–C are renderer work on today's IPC. D, F and G need a new agent action; E reuses an existing load path. Dates use the app's formatter, so the spec's “12 Mar 2026” reads “Mar 12, 2026”.

A · Find bar

Ctrl+F (⌘F on macOS), a search button in the thread header, or typing in the topbar field while its badge reads #deploys opens a find bar under the header. It matches case-insensitively over the verified, decrypted rows the conversation already holds, highlights every match, marks the current row more strongly and counts from the newest match. Today the field's accessible name is “Search #deploys”, but it filters only team and channel names, so “canary” empties the column. Use Today and Proposed in the bar above to compare.

Findings

  • chat-ux-history-searchShips on today's data
    The bar searches the HistoryWindow the thread already renders, with no new IPC. Today the field names #deploys only in its accessible name (topbar.tsx:158, search-field.tsx:63) and filters names (chat-teams.tsx:347). Proposed: a visible #deploys badge, and typing searches the channel it names. The badge's × (or Backspace in the empty field) is also new and returns the field to filtering names.
  • chat-ux-history-searchShips on today's data
    README.md:743-745 describes a “conversation header's search button” that chat-thread.tsx:169-192 does not draw. Proposed: add that button and have it open the find bar, then describe it and the topbar badge in the README.

B · Search older

The link reads up to 5 older pages (250 rows) per click, using the same History request as Load older messages, and keeps only a reference to each matching row: sequence, sender, time and a snippet. The conversation keeps its 50 rows. Searching therefore never reaches the 1,000-row or 8 MiB ceiling, past which conversationResult throws chat-limit instead of trimming (conversation-model.ts:89). A found row opens through the anchored load shown in E, which replaces the window rather than growing it. Cancel stops after the current page.

Findings

  • chat-ux-history-searchShips on today's data
    Ships on ChatAction::History with a before cursor. The scan is a transient pass that holds only hit references. If a later version adds pages to the window instead, it must follow the trimming policy from chat-ux-history-window-sliding first.

D · Messages in ⌘K

The palette gains a Messages scope after Channels (today's scopes are all, items, stores, people and channels, search-palette.tsx:55). Results are grouped by team and channel, newest first, each with author, date and a snippet, and capped at six per group like SEARCH_GROUP_LIMIT. All does not start a scan: its last row offers “Search messages for …”. The footer says where matching happens, because the agent reads ordinary history pages and matches in memory. Use Today above to see today's palette.

Findings

  • chat-backend-history-searchNeeds agent/IPC
    A new ChatAction::Search {channel, query, before?, page_budget} (foks-agent-proto/src/chat.rs:9 has History and NotificationHistory only). It reads backward through verified read_chat_thread windows, matches case-folded substrings in memory, and returns hits with scanned_through. Each call stops at about 20 pages or 4 MiB and can be cancelled. It takes the exclusive profile session per window and releases it between windows, so sends and inbox sync are not blocked. Cross-channel search gives each channel a smaller budget. No protocol or server change.
  • chat-ux-history-searchNeeds agent/IPC
    The scope chip, grouping and footer are desktop work, but they have nothing to show until the agent action exists. The chip carries a “Needs agent/IPC” tag in this mockup.

  • Use ↑ ↓ to move, Enter to open and Tab to change scope. Type a new query to start a new scan; Esc stops a running scan, then closes.
  • Press Ctrl K from the app window to open the palette fresh.

E · Open a result

Selecting a result closes the palette and opens the channel around that message with the anchored load from chat-unread-anchored-open: one History request whose before cursor sits 25 rows past the message. The message is highlighted for 2 seconds and takes focus. The window is detached, so Load newer messages and Jump to latest lead back to the newest page. Older matches from the find bar in B open the same way.

Findings

  • chat-ux-history-searchShips on today's data
    The anchored load and the highlight run on today's History IPC (before and after cursors, foks-agent-proto/src/chat.rs:37). The anchored mode itself is the desktop change proposed in chat-unread-anchored-open; this path also serves older matches found by the find bar.
  • chat-backend-history-searchNeeds agent/IPC
    Opening from the palette depends on results from the agent scan in D.

F · Search further

Search further passes the oldest sequence reached as before, so each call continues where the last stopped. The second call covers every readable channel back to Mar 12, 2026 and adds three older matches. Rows that fail verification are never matched; the palette says so and names where they are. The date shown is the newest of the per-channel stopping points, so everything after it was searched in every channel.

Findings

  • chat-backend-history-searchNeeds agent/IPC
    Each call returns scanned_through per channel and a count of rows skipped for incomplete verification.
  • chat-ux-history-searchDeferred
    A persisted index is out of scope. If scan cost proves too high, it must be sealed under the vault key like PendingChatStore (foks-agent/src/chat.rs:500), never plain FTS5, whose shadow tables store plaintext tokens. The policy change goes into book/16-chat.qmd first: durable chat state holds no plaintext today (lines 139 and 301).
