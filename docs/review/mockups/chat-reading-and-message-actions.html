A · Rendering

In Saturday's release thread in #deploys, the bare release-notes URL is a link with its trailing period left as text, and a blank line keeps two paragraphs apart. Code blocks sit on a grey surface with a copy button shown on hover or focus, and a block over 20 lines shows its first 12 lines and Show all 120 lines. @satoshi is marked as a mention of you, @priya.n as a plain mention, and list bullets sit inside the text column.

Today the URL is plain text, links look like body text, the paragraphs run together, every block has a permanent Copy code button and the 120-line log fills the thread. Use Today, Proposed, and Light and dark in the bar to compare.

Findings

  • chat-ux-message-renderingShips on today's data
    A bare-URL alternative in the inline pattern (message-text.tsx:88) with trailing .,;:!? and unbalanced ) trimmed, passed through safeChatLink. Blank lines become spacing instead of being skipped (line 177). pre gets a surface, padding and a copy button shown on hover or focus-within (line 150, chat.css:1260). Lists get padding inside the body column.
  • chat-ux-message-renderingShips on today's data
    @name becomes a pill only when the name is in partyNames; your own username gets the highlighted pill. Collapsing past 20 lines stands in for the recommended 360px max-height, so a long block never adds a second scroll region inside the thread.
  • chat-ux-message-renderingDeferred
    Mentions stay text styling: no notification and no mention count. Mentions as a protocol feature remain deferred (ISSUES.md, Existing disclosed limitations).

B · Link check

lee's "here" link is followed by its destination host, and every link shows its full URL on hover or keyboard focus. sam.ortiz's message labels a link https://acme-bank.example/login but points at acme-bank.evil.example, so the label gets an amber underline and icon. Clicking it opens Check this link with Cancel focused; a link whose label is its URL, or a plain word such as "here", opens directly.

Today both links look like body text, and the second opens acme-bank.evil.example with no prompt and no sign of where it goes.

Findings

  • chat-ux-link-label-spoofingShips on today's data
    The host comes from new URL(url).hostname, which is already punycode, so a lookalike host shows as xn--…. The comparison runs in the renderer before openChatLink (message-text.tsx:102). The check sheet's Copy link copies the destination with the existing copyText.
  • chat-ux-link-label-spoofingDeferred
    open_chat_link (chat.rs:340) is unchanged and gets no confirm flag: the renderer would choose the flag, and the host never sees the label. A host-enforced step would be a native dialog naming the destination host for every chat link.

Try

  • Hover or Tab to each link.
  • Click the acme-bank link. Esc or Cancel returns focus to it.
  • Switch to Today and click the same link.

C · Hover actions

Hovering priya.n's message shows a small bar at its top right: Copy, Quote reply and More, each with a tooltip. More holds Details. Right-clicking a message opens the same actions as a menu. Today the only action is Copy message, in a right-click menu on the text.

There are no React, Edit or Delete buttons, enabled or disabled.

Findings

  • chat-ux-message-actionsShips on today's data
    A MessageActions component in each article.chat-message, shown on :hover and :focus-within. Copy message moves into it from the text's context menu (message-text.tsx:182).
  • chat-ux-message-actionsNeeds protocol/server
    Edit, Delete, Reaction and Reply types are reserved (realtime.rs:205), but the server rejects every non-Basic send (messages.rs:16), so none of them appear.
  • chat-ux-message-actionsDeferred
    Copy link to message is not shown. Store refs are local JSON (vault.rs:209) and no URI scheme is registered, so it needs a portable id (team id, channel id, sequence), in-app routing in MessageText and optionally an OS URI scheme.

Try

  • Hover any message, then select Copy or Quote reply.
  • Right-click a message.

D · Keyboard

The message list takes one tab stop: the current row, then that row's links and action bar. Links in other rows leave the tab order until their row is current. ↑ ↓ Home End move between rows, the ring shows the current one, and its action bar appears as on hover. A hint under the list names the keys. Enter or Shift+F10 opens the same actions as a menu anchored to the row, and Esc returns to the composer.

Shift+F10 and the action bar are the keyboard routes on macOS, where WKWebView has no ContextMenu key.

Findings

  • chat-ux-keyboard-a11yShips on today's data
    Part 2 of the recommendation: a roving tabindex over the articles in ChatThread. Today articles are not focusable and the list is a plain labelled div (chat-thread.tsx:241).
  • chat-ux-message-actionsShips on today's data
    The menu lists the same actions as the bar, so pointer and keyboard users reach the same things.

Try

  • Tab into the message list, or click a message, then use the arrow keys.
  • Press Enter, then Esc; press Shift+F10; press Esc on a row.

E · Quote reply

Quote reply writes a quote as plain text: a header line with the author and time, then the first lines of the message, each starting with >. The caret goes below it, and the Quoting priya.n chip removes the quoted lines in one step. Sending posts an ordinary Basic message, and consecutive quote lines render as one block. Today a reply has to quote by hand: copy the message from its right-click menu, paste it and add the > marks.

Findings

  • chat-ux-message-actionsShips on today's data
    The text goes in at the caret through service.setDraft. Blockquotes already render (message-text.tsx:173); no Reply message type is used.

Try

  • Remove the chip, then quote another message from its action bar.

F · Details

More, then Details, lists the sender, the server's receive time, the sender's clock and the sequence number. Today these appear only in the time element's tooltip (chat-thread.tsx:349). Verification is worded for the page: "History on this page checked" or "Earlier messages on this page could not be checked". Use Page check in the bar to see both; the incomplete case also shows the band the app already draws above the thread.

Findings

  • chat-ux-message-actionsShips on today's data
    insert_time, send_time and sequence are on every message. HistoryWindow holds one verification flag per loaded page (conversation-events.ts:59), which is all the popover claims.
  • chat-ux-message-actionsNeeds agent/IPC
    A result for one message needs the agent to return predecessor_unchecked per row. The dashed box in the popover marks where it would go.

Try

  • Switch Page check to Incomplete.

G · Shortcuts

Pressing ? outside a text field, or the keyboard button in the channel header, opens Keyboard shortcuts. The filter narrows the list as you type. It lists only bindings that exist once this change ships, written for your platform (⌘ and ⌥ on macOS, Ctrl and Alt elsewhere). Composer bindings are a separate group, marked With composer refinements. Today the app has no list of its shortcuts.

Findings

  • chat-ux-keyboard-a11yShips on today's data
    Part 6. Alt+↑/↓ is free because Alt+←/→ is back and forward (back-inputs.ts:19). In the composer it applies only when the caret is on the first or last line, since macOS uses ⌥↑/↓ to move to a paragraph boundary.
  • chat-ux-keyboard-a11yShips on today's data
    In the composer group, Enter and Shift+Enter work today. Bold, italic, code and ↑ to edit your unsent message come from the composer mockup.

Try

  • Type "unread" or "alt" in the filter.
  • Close the sheet, then press ?.
