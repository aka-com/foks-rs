    Scenario

    From Kit.data, with two page-local additions: three unread messages in Engineering #general (10:31 to 10:42, the last from sam.ortiz mentioning @satoshi), and in state B a new admins-only channel #oncall. Engineering has 6 members: satoshi (Owner, you), priya.n and vitalik (Admins), sam.ortiz, lee and deploy-bot (Members). Each tab starts from its own preset; changes last until you switch tabs or press Reset.

    A · Readers

    The #incidents info panel lists its 3 readers with each one's role and whether they can post, and names the 3 team members who cannot see it. Today the panel has a Visibility row and a Members count of 6, the whole Engineering roster, although only admins and owners can read the channel. The header leads with "3 readers", because the description does not say who reads. The panel is 288px wide instead of 260px to fit the reader rows. Use Today and Proposed above the window to compare; Manage in Teams opens the roster.

    Findings

    • chat-ux-channel-audienceShips on today's data
      Add channelAudience() next to readersOf() in model/readers.ts: normalize Member (n), keep the user parties whose role passes admits(destination_role, read_role), and mark those that also pass write_role. Both roles are already in chat-contract.ts.
    • chat-ux-channel-audienceShips on today's data
      Role labels use roleTextWithoutBand(), which has no callers today. The Alerts row in this state is today's control, unchanged; state C replaces it.

    B · New channel

    The empty state of a new admins-only channel says who will read the first message: "Only the 3 admins and owners of Engineering can read it." Today the sentence counts the whole roster, "Only the 6 members of Engineering can read it", at the moment people decide what to post. The channel has no description, so the header shows "3 readers" where today it shows "6 members". See who can read opens the panel from state A.

    Findings

    • chat-ux-channel-audienceShips on today's data
      chat-screen.tsx passes every party on the store as memberCount. Passing the reader count from channelAudience() fixes the header, this sentence and the panel together, including member-tier channels whose read role has a band above some members'. Add render tests for both cases.

    C · Channel alerts

    The Notifications section of #deploys offers All messages, Mentions only and Nothing, with Mute channel as a separate switch. Muted, #deploys is dimmed and its 2 unread drop out of the Engineering total, the Chat count in the rail and the app icon; fold Engineering to see its heading count. Mentions only alerts when a message contains @satoshi, matched as text on this device. Today Alerts can be set to None but the channel still counts toward every badge: switch to Today and try it.

    The three-way control and the switch are proposals; today the panel has a single Alerts select. Keyboard: arrow keys move between the modes, Space toggles the switch, Esc closes the panel.

    Findings

    • chat-ux-local-muteNeeds native shell
      Add a muted set and a mentions mode to the chat_local Settings, keyed by notificationKey and bounded at 4096 like overrides, and merge muted = server.muted || local.muted into the published inbox projection. teamUnread, channelUnreadTotal and the rail then exclude the channel without changes. The server's muted flag cannot be set on the pinned protocol.
    • chat-ux-local-muteNeeds native shell
      Mentions only matches @satoshi case-insensitively at word boundaries in the first 256 characters the notification consumer reads (notification-policy.ts), and the caption says it is a text match. The mode needs a third value in the chat_local overrides, which today hold only on or off.
    • chat-backend-notification-prefs-mentions-namesDeferred
      Protocol mentions with resolved identities stay deferred, as ISSUES.md lists them.

    D · Team menu

    Right-click the Engineering heading, or focus it and press Shift+F10, for the team menu: alerts for Engineering and Mute all channels. Go to team and the add-people items open the team's page in Teams. A channel without its own choice follows the team default, and its info panel says so. Engineering is folded, so its heading carries the team's 5 unread; muting all channels removes that count and the Chat count in the rail. The three choices sit in the menu as radio items rather than in a submenu, so each is one arrow key away.

    Findings

    • chat-ux-local-muteNeeds native shell
      Per-team alert defaults live in the chat_local Settings beside the muted set, with the same bound. Today's team menu items, Go to team and the three add-people actions, stay.

    E · Desktop alerts

    Settings › Preferences › Desktop alerts gains a platform status row, Group alerts by channel, Show unread count on app icon, and a live preview of the alert for the 3 new messages in Engineering #general. With previews on, the title names the channel and team and the body names the sender; with grouping on, the alerts stack as one entry. Switch the platform above the window: today every non-macOS build says "Desktop alerts are unavailable in this build." Click the preview to open the channel.

    Findings

    • desktop-native-linux-notifications-and-badgesShips on today's data
      Enable desktop alerts and the previews option exist today in NotificationSettings; this page renames "Include message previews" to "Show message previews".
    • desktop-native-linux-notifications-and-badgesNeeds native shell
      Add platform/linux.rs over zbus, already a Linux dependency: GetServerInformation for the status row, Notify with a per-channel replaces_id, and ActionInvoked to open the channel. Un-gate route_current, activate and delivery_failed from cfg(macos), set threadIdentifier per channel on macOS, take the title from a bounded channel label, and update PERMISSIONS.md. The macOS row also needs the session to report the authorization status: today the renderer learns of a denial only when enabling alerts fails.
    • chat-ux-local-muteNeeds native shell
      Channel alerts lists the channels with their own setting; Reset returns one to its team default.
    • desktop-native-linux-notifications-and-badgesShips on today's data
      The sender's name in the preview body comes from the team roster in the renderer, as the thread's names do, and counts toward the 256-character body bound. A sender who has left the team shows as a short ID until the agent supplies sender labels.

    F · App icon

    The FOKS icon in the Dock shows 3, the unread in Engineering #general; muted #deploys keeps its 2 out, by the same rule as the rail. Right-click a channel to mute or unmute it, or open #general to read it, and the icon follows. The count clears when FOKS locks.

    Findings

    • desktop-native-linux-notifications-and-badgesNeeds native shell
      A set_unread_badge(count) command calls set_badge_count behind require_main_window and is cleared in chat_local::conceal. On Linux the count shows only in docks that read the Unity launcher API, such as Ubuntu Dock.
    • chat-ux-local-muteNeeds native shell
      The icon count is the rail's total, taken from the projection with the local muted set merged in.

    G · Sync

    A later step syncs alert modes, mutes and team defaults to your other devices. With the setting on, a change waits as pending until the agent has written it; Sync now clears it here. Each channel's setting is its own record and the newest write wins, so a change to #deploys on Travel Mac does not undo a team default set on this MacBook Pro.

    Findings

    • chat-backend-notification-prefs-mentions-namesNeeds agent/IPC
      The agent merges preferences into ChatConversation and syncs them, encrypted, through a reserved path in your personal KV store, so the server holds only ciphertext. No realtime protocol change is needed.
    • chat-backend-notification-prefs-mentions-namesNeeds client library
      A chat_channel_preferences table that delta application never touches; today the soft store overwrites hidden and muted on every delta.
    • chat-ux-local-muteNeeds agent/IPC
      The native muted set, team defaults and per-channel overrides migrate into the agent table once.
