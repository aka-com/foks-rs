    A · Trash rows

    Every vault that holds items ends with a Trash row: Personal shows Trash 4, Household Trash 2, and Engineering an empty, dimmed Trash. Today Delete writes a RemoveKv tombstone behind a sheet that says "This cannot be undone." (write-workflows.tsx:1489), so one mis-click destroys a credential for good. With Trash, Delete becomes a MoveKv into /.trash in the same vault, which can be reversed.

    Findings

    • fe-product-trash-undoNeeds native shell
      The host creates /.trash/<role-tag>/ with mkdir_p and moves entries in with the existing MkdirKv and MoveKv operations. No protocol change.
    • fe-product-trash-undoShips on today's data
      The Trash row, its count, and hiding /.trash from folders, All items and search are computed from catalog paths, which folderTree (scope.ts:67) already walks. Other FOKS clients, such as the Go CLI, list .trash as an ordinary folder; book/20-desktop.qmd has to say so.
    • fe-product-trash-undoDeferred
      Emptying Trash automatically after a set age comes after single items, Undo and folders.

    Try

    • Select Trash under Personal or Household.
    • Right-click a folder in the tree, or focus it and press Shift+F10.

    B · Delete and Undo

    Move to Trash, or Delete on a selected row, removes github.com from /logins at once and shows "Moved github.com to Trash" with Undo for 8 seconds; ⌘Z does the same while the toast shows. There is no confirmation sheet, because the step can be reversed. Switch to Today above the window for the current sheet.

    Findings

    • fe-product-trash-undoNeeds native shell
      A host command names the entry <UTC yyyymmddThhmmss>~<percent-encoded path>, with a hashed name and a sidecar file past 255 bytes, and issues MoveKv: a source tombstone plus a destination dirent with a fresh dirent ID (write.rs:655, 1238).
    • fe-product-trash-undoShips on today's data
      Undo uses the toast action button that already exists (toasts.tsx:16). Without new IPC, it reloads the catalog, finds the entry by its trash path and moves it back, because selected_item needs the entry in the catalog.
    • fe-product-trash-undoNeeds agent/IPCNeeds client library
      A direct Undo needs KvWriteReport, the MoveKv response and MutationResponse to return the destination dirent ID and version. Today the desktop decodes only {applied} (vault-catalog.ts:363).

    Try

    • Press Undo, or ⌘Z, before the toast closes. Pointing at the toast pauses it.
    • Select fastmail.com and press Delete, or use Move to Trash in the details panel.

    C · Folder to Trash

    The folder menu offers Move folder to Trash. Today it shows Delete folder, disabled with "Deleting folders is not supported by the desktop agent.", because remove_item_operation rejects directories (vault.rs:707). MoveKv moves the folder and everything in it as one mutation, so a child another device adds at the same moment moves with the folder instead of being destroyed by a recursive delete.

    Findings

    • fe-product-trash-undoNeeds native shell
      The host accepts a directory for the trash move and picks the trash by the folder's own read role, since its children's names stay sealed under the folder's key.
    • fe-product-trash-undoShips on today's data
      The menu item, the Undo toast and the folder's row in Trash reuse today's menu, toast and list components.

    Try

    • Switch between Today and Proposed above the window.
    • In Proposed, choose Move folder to Trash, then Undo.

    D · Trash view

    Selecting Trash under Personal opens "Trash · Personal" with Name, Original location, Deleted and Size, newest first, and a danger button, Empty Trash…. Each row has Restore and Delete permanently, and selecting a row shows where the entry is stored. Delete permanently uses the reworded warning "Removes it for everyone. Earlier encrypted versions may remain on the server."

    Findings

    • fe-product-trash-undoShips on today's data
      Original location and Deleted are parsed from the entry name. Restore is a move_item back to the original path, a command the host already has.
    • fe-product-trash-undoNeeds native shell
      Delete permanently and Empty Trash use RemoveKv, recursive for folders, and the host allows them only inside /.trash.

    Try

    • Restore openai-api-key, then press Show in the toast.
    • Select a row and press Delete for Delete permanently, or Shift+F10 for its menu.

    E · Restore conflict

    Restoring github.com finds another github.com at /logins/github.com, the one created after the old copy was deleted. The sheet names the path, compares the two, and offers "Restore as github.com (restored)" or Cancel, so nothing is overwritten.

    Findings

    • fe-product-trash-undoShips on today's data
      The check reads the loaded catalog, and restoring as a copy is a move_item to a new name. A conflict the agent reports at write time goes through the existing conflict handling in write-workflows.tsx.

    Try

    • Restore as github.com (restored), then press Show in the toast.
    • Cancel, or Esc, leaves the entry in Trash.

    F · Empty Trash

    Empty Trash… asks "Permanently delete 4 items?" and says that earlier encrypted versions may remain on the server: kv_dirents keeps every version (kv.sql:60) and the server does not delete them. The sheet lists what goes, and Cancel has focus.

    Findings

    • fe-product-trash-undoNeeds native shell
      RemoveKv runs on each entry under /.trash, recursive for the tax-2024 folder. Outside /.trash the host keeps refusing folders.

    Try

    • Empty Trash, then Reset to start again.

    G · Team Trash

    Household has its own Trash. A band says items keep their read access in Trash and owner-only items are visible only to owners; lease-2024.pdf carries a lock labelled Owners only. hal, the Household member, sees only guest-password-2025.

    Findings

    • fe-product-trash-undoNeeds native shell
      There is one trash folder per read role: /.trash/owner/, /.trash/admin/ and /.trash/member-<visibility>/. Dirent names are sealed under the destination directory's keyset, so one shared folder would expose names to the wrong role. Each folder is created with its read role and a write role low enough for everyone who can delete items of that role.
    • fe-product-trash-undoShips on today's data
      The band, the lock and the Visible to row in details come from the role of the trash folder an entry sits in.

    Try

    • Restore guest-password-2025 to /wifi.
    • Select lease-2024.pdf to see it is stored under /.trash/owner/.

    H · Multi-select

    ⌘-click and Shift-click select several rows; checkboxes appear on hover and stay once a row is checked. The column header becomes "3 selected · Move to… · Move to Trash · Download · Clear". Move to… replaces today's free-text path (move-item-sheet.tsx:113) with the vault's folder tree, an inline New folder and the preview "Moves 3 items to /env/prod"; dragging rows onto a folder does the same, and a progress sheet reports each item with Retry failed.

    This tab adds six loose items at the top of Personal, as an import from another password manager leaves them.

    Findings

    • fe-product-organize-bulkShips on today's data
      A MultiSelection (ordered keys plus an anchor), the toolbar, the picker built from folderTree, New folder through createFolder (already mkdir_p, lib.rs:1528) and sequential move_item calls with per-item outcomes are renderer work.
    • fe-product-organize-bulkShips on today's data
      Drag uses pointer events and elementFromPoint on rows that carry data-folder-store, because the window's native dragDropEnabled handler stays reserved for files dropped from the OS.
    • fe-product-organize-bulkNeeds native shell
      Move to Trash for several rows needs the Trash host commands. Download of several files to one folder needs a folder picker, because download_file opens one save dialog per file.
    • fe-product-organize-bulkDeferred
      Writing several dirents in one kvPut waits until a measured need appears.

    Try

    • Pick a picture above the window: Selection, Move to…, Drag or Progress.
    • In Selection, choose Move to…, pick env › prod and press Move. The last item fails once; press Retry failed.
    • Drag the checked rows onto logins in the tree, or onto Trash.
    • Space toggles the focused row, Shift+Arrow extends, ⌘A selects all and Esc clears.
