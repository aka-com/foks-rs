Scenario

Engineering on Acme, signed in as satoshi, the team's owner. The plan names vitalik as the current user; this page follows Kit.data, so vitalik appears in completions as an Admin, and #incidents has three members who cannot read it (sam.ortiz, lee, deploy-bot) instead of two.

Use Today and Proposed in the bar to compare any state with the current composer (chat-thread.tsx:418). States A to F change only the renderer in apps/desktop and ship on current IPC; G needs the agent.

A · Hints

With the message box focused, a faint line under it says what Enter and Shift+Enter do and which markers format text. The ? button opens a cheat sheet listing exactly what messages render: inline code, bold, italic, http and https links, fenced code blocks, lists and quotes. Today none of this is written anywhere, so people learn that Enter sends by sending, and cannot tell in advance that a # heading or _underscores_ stay literal.

Findings

  • chat-ux-composerShips on today's data
    The hint row and sheet are static copy beside the textarea. Each row matches a branch of message-text.tsx (inline at :85, blocks from :140), so a test can render every example through MessageText and keep the two in step.

Try

  • Press Esc inside the sheet or select its close button; ? opens it again.
  • Click the message box: the hint line stays while it has focus.

B · Toolbar

In a window wider than 900px, six buttons appear above the text while the box has focus: bold, italic, code, code block, quote and list. , and wrap the selection in **, * and `; puts whole lines in a ``` fence. Pressing the same key again removes the markers, and undoes a wrap. Narrower windows hide the buttons but keep the keys.

Findings

  • chat-ux-composerShips on today's data
    A branch in the existing onKeyDown (chat-thread.tsx:433). The code-block chord avoids Ctrl Shift C, which Chromium-based webviews use for the element inspector when developer tools are on. Ctrl/⌘ E and the chord still need checking against the native Edit menu on each platform.

Try

  • “below 0.05%” is selected and bold, so B shows as pressed. Press or select B to remove the markers, and again to put them back.
  • Select both lines of a multi-line draft and choose Quote or List.

C · Mentions

Typing @ and a few letters lists matching team members with their avatar and role. ↑ and ↓ choose, Enter or Tab inserts “@priya.n ”, and Esc closes the list until the next @. The result is plain text, so the message format and the server do not change. In #incidents, which only admins and owners can read, the list holds only people who can read it and says how many members are left out; today a name has to be typed from memory with no hint that the person cannot see the message.

Findings

  • chat-ux-composerShips on today's data
    Candidates are the team's user parties that partyNames(snapshot, storeId) (presentation.ts:115) lists, which is every user of the team. The role tag and, for an admin-tier channel, the filter to admins and owners use each party's destination_role from the same snapshot; you are left out. The roster has no bot flag, so deploy-bot is listed as a Member. Mentions as a protocol feature stay deferred in ISSUES.md.

Try

  • Switch to #incidents in the bar, or open it in the column and type @.
  • Type @ortiz: names also match from the part after a dot.

D · Drafts

A draft left in #random stays when you switch to #general, as it does today, and the #random row now says so with a pencil and “Draft”. The open channel shows no marker because its draft is in front of you. Today the column gives no sign, so a half-written message is easy to forget.

Findings

  • chat-ux-composerShips on today's data
    The channel row (chat-teams.tsx:927) adds the caption and glyph when sends.draft(storeId, channel.id) is non-empty. The caption joins the row's label as “#random · Draft”.
  • chat-code-send-revision-rerenderShips on today's data
    Each keystroke today calls setDraft, which re-encodes every draft of every team (send-service.ts:443) and bumps one global revision (:224), so the chat screen, conversation and composer re-render and the message list maps up to 1,000 rows. A DraftStore with per-(store, channel) subscriptions and a per-store has-draft flag limits a keystroke to the composer, and the column to empty and non-empty changes. The message list also has to move into a React.memo component, because ChatThread renders the composer and subscribes itself (chat-thread.tsx:112).

E · Size limit

The pasted sample is 62,236 bytes of rollout logs. From 90% of the 65,536-byte limit, the space left appears at the right of the hint line in amber, here “3.3 KB left”; past the limit it turns red, says how far over the message is, and Send is disabled. The unit is bytes because the limit is UTF-8 bytes: the sample's → and µ take 3 and 2 bytes, so its 60,000 characters would give a wrong count. Today the meter appears at 75% as “61 KiB of 64 KiB”, which says what is used, not what is left.

Findings

  • chat-ux-composerShips on today's data
    nearLimit moves from 0.75 to 0.9 (use-chat-composer.ts:75) and the label uses fmtSize's KB, as Files does, with “bytes” spelled out below 1 KB instead of “B”. overLimit stays draftBytes > CHAT_TEXT_BYTES and still disables Send.
  • chat-code-send-revision-rerenderShips on today's data
    Today every keystroke in any channel encodes this 62 KB draft again, with every other draft, to check the shared draft quota (send-service.ts:443). A byte total kept by delta encodes only the draft being edited.

Try

  • Select Add 1 KB in the bar until the count turns red.
  • Paste your own text: the count follows any input.

F · Unsent message

“Can we skip the canary?” did not reach Acme and sits at the end of #deploys as Not sent. With the box empty, the hint line says ↑ edits it; pressing ↑ moves the text into the box and removes the row, as the Edit link does. If the box already holds a draft, ↑ moves the cursor as usual and Edit says the draft is kept. Today only the small Edit link restores the text.

Findings

  • chat-ux-composerShips on today's data
    ↑ with an empty draft calls service.restoreDraft (send-service.ts:1114) for the newest not-sent or queued message in this channel that outgoing-row.tsx:50 marks editable. restoreDraft already refuses while a draft exists.

Try

  • Click the message box and press ↑, then Enter to send it.
  • Reset, type a word, then select Edit on the row.

G · After unlock

FOKS was locked and unlocked with drafts in #deploys and #random. Proposed: the #deploys draft is back in the box with “Draft kept on this device”, and #random still shows its marker. Today: locking unmounts the unlocked shell and stop() clears every draft (send-service.ts:253), so both are gone and nothing says so. Switch Today and Proposed in the bar, or use Simulate lock or Lock in the account menu to run it again.

Findings

  • chat-ux-composerNeeds agent/IPC
    Needs save-draft and load-draft chat actions that keep drafts in the agent's protected store, separate from SaveIntent, which means “submit this”. They must be cleared on account removal and team replacement, as stop() and the team reset (send-service.ts:357) clear the in-memory map today. This is the only part of the mockup that does not ship on current IPC.
