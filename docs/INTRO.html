An Introduction to FOKS Desktop

A plain-language guide to the desktop application: how it runs, how it keeps private keys out of the browser DOM, and how to use it for personal vaults, team secrets, and encrypted chat.

foks-desktop · Tauri v2 · React 18 · foks-agent daemon

Zero-Trust Desktop Design

FOKS Desktop is not an Electron web wrapper talking directly to cloud servers. It is a lightweight presentation layer over a local, detached resident daemon (foks-agent). Your private cryptographic keys never enter the webview JavaScript memory, clipboard operations stay inside native Rust code, and closing the app window never interrupts background sync or drops your session.

1. The Two-Process Model: A UI for a Resident Daemon

Most desktop password managers run as a single monolithic process. If the window is closed, your connection is severed; if an attacker exploits a vulnerability in the rendering engine, they gain full access to decrypted master keys in memory.

FOKS takes a fundamentally different approach by splitting the system into two distinct processes with an explicit security boundary:

1. The Presentation Shell (foks-desktop) A sandboxed Tauri v2 + React 18 interface. Manages navigation, displays decrypted entries in transient view panels, and passes opaque catalog references. Holds no private keys. JavaScript cannot execute arbitrary OS calls.
2. The Resident Daemon (foks-agent) A local background process. Owns credentials, holds the decrypted session cache, manages hard-state SQLite journals, and syncs with remote servers. Independent of the window lifecycle; survives app restarts and window closures.

Socket Security and Process Isolation

The desktop app connects to the resident daemon over a local Unix domain socket (foks-rs.sock). Before sending any request, the client strictly checks the socket's metadata:

  • Exclusive Ownership: The socket file must have permissions restricted to 0600 (owner-only read/write). If group or world bits are set, the connection is aborted immediately.
  • Effective UID Validation: The socket file owner UID must match the running user's effective UID (rustix::process::geteuid()). Other local users on the same machine cannot intercept or impersonate the socket.
  • Lockfile Protection: The daemon maintains an advisory write lock on .foks-rs.lock opened with O_NOFOLLOW, preventing symlink substitution and multi-instance database corruption.

Memory Hygiene in the Webview

When you click "Show" on a password, the secret is fetched from the daemon for that exact item version and displayed only inside the active detail panel. If you select another entry, hide the panel, minimize the app, or trigger AppLock, the cleartext secret is immediately wiped from memory. Operations like Copy value and Download file are executed directly within Rust to avoid pushing raw plaintext into the JavaScript heap or system clipboard history.

2. First Run & Device Setup: Enrolling Without Passwords

FOKS has no master password. A master password is a catastrophic single point of failure: humans choose weak words, reuse them across services, or type them into phishing websites.

When you launch FOKS Desktop for the first time, you are presented with three enrollment paths, each anchored in verifiable cryptographic keys:

  1. Create a New Account: Your machine mints a brand-new cryptographic identity. It derives an Ed25519 signing key, an X25519 Diffie-Hellman key, and an ML-KEM-768 post-quantum keypair directly from local entropy. It then presents a printed Recovery Kit.
  2. Pair with an Existing Device (KEX): If you already have FOKS running on another laptop or phone, you can link the new machine in seconds using an ephemeral 13-token pairing code.
  3. Enroll a Hardware Security Key (YubiKey): You can anchor your account keys to a physical YubiKey hardware token using PIV smartcard slots.

The Recovery Kit (HESP)

Because there is no server-side password reset, losing all registered devices would permanently lock you out of your vault. To prevent this, FOKS generates a Human-Exact Secret Phrase:

FOKS-RK1-abandon 4092 ability 1084 absorb 7192 accuse 0341 achieve 5521 acid 2091 acoustic 6812 acquire 4410 action

This 17-token phrase provides 203 bits of entropy. It is stretched via Argon2id (64 MiB memory, 3 iterations) to derive a recovery unsealing key. During normal vault re-keying (such as when a teammate leaves), members automatically re-seal the new vault key to the recovery code's registered public identity—so a printed kit remains valid for years without reprinting.

Safe Resumability with Operation Receipts

If network connectivity drops or the laptop lid closes during first-run setup, FOKS never leaves you stranded with an uncertain account state. The desktop stores non-secret setup progress and durable operation receipts in account-operation-receipts-v1. When reopened, the app queries the agent for pending operations and offers an explicit Resume setup action rather than blindly creating duplicate accounts.

3. Everyday Use: Vaults, Groups, and Encrypted Chat

Once enrolled, the desktop interface provides four primary workspaces accessible from the navigation rail:

1. Profiles & Multi-Account Switching

FOKS supports multiple active accounts on different servers (for example, a personal sovereign vault and an enterprise company server). Clicking the profile avatar in the rail opens the profile switcher. Switching accounts updates the active catalog and resets all in-memory view caches instantaneously.

2. The Vault: Encrypted Files and Key-Value Entries

The Vault stores passwords, API tokens, cryptographic certificates, and arbitrary binary files organized in a folder hierarchy:

  • Zero Plaintext Storage: Directory paths are blinded with keyed HMAC hashes (name_mac). The server cannot see file names, folder structures, or secret lengths.
  • Adaptive Size Padding: Secrets are padded into standardized buckets (small items to 32, 64, or 128 bytes; larger files to 4 KiB multiples) so network observers cannot deduce content type from ciphertext size.
  • Streaming File Transfers: Uploading or downloading large attachments does not consume excessive RAM. The desktop streams files in encrypted 700 KiB frames directly through the native bridge to the local agent's writer channel.

3. Teams and Group Collaboration

Opening a team from the Teams list displays four dedicated tabs: Members, Channels, Files, and Settings.

  • Role-Based Access Control: Members are assigned roles: Owner, Manager, Member, or Reader. Roles dictate who can invite members, create channels, or delete data.
  • Forward Secrecy on Departure: When a teammate is removed, FOKS automatically generates a brand-new Per-Team Key (PTK), creates fresh encryption boxes for remaining members, and re-encrypts all team secrets. The departed member's cached keys are immediately rendered useless.
  • Tamper-Proof Invitations: Inviting a colleague creates a cryptographically signed invitation certificate. The invite sets a strict role ceiling that cannot be escalated, even by an untrusted server administrator.

4. End-to-End Encrypted Team Chat

Each team includes encrypted real-time chat channels for secure communication:

The Active Thread Invariant

To deliver real-time responsiveness without draining laptop battery life, the desktop notification service uses adaptive polling:
• The currently active conversation maintains a strict 5-second polling interval (FALLBACK_MS = 5000) and never backs off.
• Background, unviewed channels exponentially back off up to 60 seconds (FALLBACK_MAX_MS = 60000).
• The arrival of any new message immediately resets all intervals back to 5 seconds.

4. Endpoint Security & App Lock: Keeping Secrets Locked Down

A password manager's greatest vulnerability is an unattended, unlocked laptop. FOKS Desktop integrates directly with your operating system's native hardware security layer to enforce rapid locking and biometric unlock.

Platform Biometrics Integration

FOKS avoids custom password prompts in favor of trusted OS authentication:

  • macOS: Integrates with Apple's LocalAuthentication framework. Unlocking uses Touch ID, Apple Watch proximity, or system account password (LAPolicy::DeviceOwnerAuthenticationWithBiometrics).
  • Linux: Integrates with Polkit (PolicyKit) over system D-Bus. Evaluates action org.foks.desktop.unlock, displaying the native desktop environment authorization dialog.
  • Native Credential Keystores: Master wrapping keys are stored in the macOS Keychain or Linux Secret Service (GNOME Keyring / KWallet), encrypted at rest with XChaCha20-Poly1305.

The AppLock State Machine

When AppLock activates—either by clicking the lock icon, stepping away from your machine, or letting the system sleep—the desktop initiates a comprehensive shutdown of sensitive state:

  1. Immediate DOM Concealment: All open secret values, chat messages, and folder contents are immediately obscured and removed from webview memory.
  2. Generation Counter Gate: AppLock increments an atomic 64-bit generation counter (AtomicU64 generation). Any in-flight background request issued before the lock event is automatically rejected with an app-locked or chat-interrupted error upon completion.
  3. Cache Invalidation: Catalog caches are marked stale (invalidate_catalog()). When unlocked via fingerprint or PIN, the application re-validates credentials with the daemon and reconstructs the view cleanly.
Unlocked & Active User is present; biometric confirmation passed. Opaque catalog items loaded. Detail panel shows secrets on explicit click; clipboard operations stay in Rust.
Auto-Lock / Timeout Inactivity timer expires or laptop lid closes. Webview memory wiped. Atomic generation incremented; in-flight network queries rejected.
Locked State Lock screen overlay displayed. All secret panels concealed. Only biometric unlock or app termination is accepted. Daemon continues sync.

Windows Support Status

FOKS Desktop currently supports macOS and Linux. Windows is not yet supported because native credential storage (DPAPI) and secure named-pipe IPC validation are still being implemented. FOKS deliberately refuses to run on Windows until it can guarantee the exact same process isolation and ACL verification enforced on Unix platforms.

With its two-process architecture, hardware-bound passkeys, and biometric locks, FOKS Desktop gives you sovereign control over your sensitive secrets without compromising on desktop speed or convenience.
